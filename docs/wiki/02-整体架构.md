## 1. 分层架构总览

项目采用经典的 **MV + Service** 分层（SwiftUI 生态下的 MVVM 变体），工程为 macOS 单平台，按需保留 `#if os(macOS)` 守卫：

```
┌─────────────────────────────────────────────────────────────────┐
│  App 壳层  MemontaApp.swift + AppDelegate                       │
│  单实例守卫 / fd 限制 / HF 镜像 / ModelContainer / 菜单命令        │
├─────────────────────────────────────────────────────────────────┤
│  视图层  Views/                                                   │
│  RootView（NavigationSplitView 枢纽）                             │
│  ├── RecordingListView（录音+笔记合并侧边栏）                      │
│  ├── RecordingDetailView → Transcript / Summary / VideoUnderstanding│
│  ├── QuickNoteDetailView / Screenshot 截图与标注组件              │
│  ├── SettingsView / HelpView / OnboardingView / PrivacyConsent   │
│  └── MarkdownView / TextFindReplace                              │
├─────────────────────────────────────────────────────────────────┤
│  ViewModel 层  ViewModels/（@MainActor @Observable）              │
│  RecordingViewModel（转写/总结/待办/录音编排核心枢纽）      │
│  QuickNoteViewModel / SettingsViewModel                          │
├─────────────────────────────────────────────────────────────────┤
│  服务层  Services/（状态型服务多为 @MainActor @Observable）   │
│  ① 录音采集：MeetingRecorderService（总控）                        │
│     ├ MicCaptureService（AVAudioEngine）                          │
│     ├ SystemAudioCaptureService（ScreenCaptureKit）               │
│     ├ AppMuteDetector（AX 轮询）/ MicMuteMonitor（CoreAudio）      │
│     └ AudioConverter（时长/转换）                                  │
│  ② 转写管线：WhisperLocalService / WhisperAPIService              │
│     ├ SpeakerDiarizationService + VoiceprintStore（分离+声纹）     │
│     ├ TranscriptDictionaryService / ChineseConverterService      │
│     └ TranscriptCache（渲染缓存）                                  │
│  ③ 智能功能：LLMService / TodoExtractionService                   │
│     ├ KeyframeExtractor / VideoUnderstandingService（视频理解）     │
│     ├ RemindersService（EventKit）/ PIIScrubService               │
│     └ PIIScanService（本地模型扫描）                                │
│  ④ 截图子系统：ScreenshotManager / VisionOCRService               │
│  ⑤ 同步与安全：FileSyncService / CloudSyncService                  │
│     └ EncryptionService（AES-GCM + Keychain）                     │
│  ⑥ 系统集成：MenuBarController / GlobalHotkeyManager              │
│     └ RemindersURLDiagnostic / MainActor+AssumeOnMainThread      │
│  ⑦ 任务调度：TaskCenter（全局处理队列 + AsyncClassGate 资源门）    │
├─────────────────────────────────────────────────────────────────┤
│  数据层  Models/                                                   │
│  SwiftData：AudioRecording ⇄ TranscriptSegment、LLMConfig、       │
│             QuickNote（截图作为图片型 QuickNote）                   │
│  值类型配置：STTConfig / RecordingConfig / TodoItem(+TodoDocument)│
│  磁盘权威源：~/Documents/Memonta/yyyy-MM/yyyyMMddHHmmss[-N]/ 文件夹体系        │
├─────────────────────────────────────────────────────────────────┤
│  三方依赖（SPM）：WhisperKit · KeychainAccess · SherpaOnnx         │
└─────────────────────────────────────────────────────────────────┘
```

**分层规则**：View 只依赖 ViewModel 与 SwiftData `@Query`；ViewModel 编排服务；服务之间通过单例引用或 `NotificationCenter` 解耦通信；跨 actor 传值用值类型快照（如 `LLMConfigSnapshot`）避免传递 SwiftData 对象。

### 1.1 普通 / 专业体验边界

`AppExperienceStore` 是 SwiftUI 可观察的模式状态，`AppExperiencePreference` 是 AppKit 菜单、热键与后台代码共用的无 UI 存取层，`FeaturePolicy` 统一判定能力可见性与是否允许发起。`EffectiveSettingsResolver` 在任务边界把用户保存的专业设置解析成本次实际使用的录音、STT、截图与 PII 策略。

两种模式共用同一 target、SwiftData schema、文件格式与服务实现。切换模式不会重写专业配置；普通模式的会议场景和本地转写模型路径使用独立偏好。新用户默认普通模式，旧版已完成引导的用户在首次迁移时保持专业模式。截图/录屏等全局入口同时在菜单、热键、RootView 通知接收和服务边界校验，不依赖单一视图隐藏保证边界。

## 2. 核心数据流

### 2.1 会议录音 → 转写 → 总结（主链路）

```
用户点击「开始录音」（菜单栏/侧边栏）
  → RecordingViewModel.startMeetingRecording
  → MeetingRecorderService.startRecording
      ├─ 磁盘预检（≥500MB）→ 创建 ~/Documents/Memonta/yyyy-MM/yyyyMMddHHmmss[-N]/
      ├─ 按 RecordingSource 启动采集：
      │   ├─ .microphone → MicCaptureService（AVAudioFile，CAF/PCM 分片）
      │   ├─ .systemAudio → SystemAudioCaptureService（SCStream，WAV/PCM 分片）
      │   └─ .mixed → 双路并行（mic + sys 各自分片）
      ├─ 每 300s 分片轮转（rotateSegment/rotateWriter）
      ├─ AppMuteDetector（AX 1s 轮询 Teams/Zoom 静音按钮）
      └─ MicMuteMonitor（CoreAudio mute 属性监听）
  ↓
用户点击「停止录音」
  → stopMeetingRecording → stopRecording
      ├─ mergeSegments：AVMutableComposition 双轨混音 → m4a
      │   （失败回退单轨拼接；崩溃遗留分片校验时长后恢复）
      └─ 创建 AudioRecording 记录 + saveMetaToFolder（meta.json）
  ↓
用户点击「转写」/「一键处理」（单条任务经处理队列调度，见 §3.4）
  → 投递到 TaskCenter 的 Job，转写步骤调用 RecordingViewModel.startTranscription
      ├─ 本地模式：WhisperLocalService（WhisperKit/CoreML，串行门）
      ├─ 云端模式：WhisperAPIService（multipart，>25MB 分片）
      └─ 后处理链（顺序固定）：
          ① SpeakerDiarizationService（可选，按时间重叠回填 speaker）
             └─ VoiceprintStore 声纹识别（可选，替换为注册姓名）
          ② ChineseConverterService 繁简归一化
          ③ TranscriptDictionaryService 词典纠正（精确 + 拼音）
          ④ EncryptionService 加密 → TranscriptSegment[] 入库
          ⑤ 转写文件写盘（transcript.json）
  ↓
用户选择 LLM 配置 → 「生成总结」
  → RecordingViewModel.generateSummary
      ├─ PIIScrubService.scrub（仅云端 LLM 且开关开启）
      ├─ LLMService.generateSummary（SSE 流式，onToken 逐段渲染）
      ├─ PIIScrubService.restore（流式全文还原）
      ├─ 加密保存 recording.summary + summary.md 写盘
      └─ LLMService.generateTitle 自动命名
  ↓
用户点击「拆解待办」
  → TodoExtractionService.extract（JSON 结构化输出）
  → PIIScrubService.restore(TodoDocument)
  → TodoDocument 持久化（todos.json，加密）
  → 用户确认 → RemindersService 写入系统提醒事项（EventKit）
```

### 2.2 截图 → 图片笔记（辅链路）

```
全局热键 ⌃⌘S（Carbon）或菜单栏/应用内菜单
  → GlobalHotkeyManager → NotificationCenter(.screenshotHotkeyPressed)
  → RootView → ScreenshotManager.startCapture(mode)
      ├─ 权限预检（CGPreflight/CGRequestScreenCaptureAccess）
      ├─ ⌃⌘W 全屏直拍：captureFullScreenDirect（鼠标所在屏，SCScreenshotManager）

          ├─ 冻结屏幕图 → 框选 / 窗口拾取（SCShareableContent）

  → RootView.handleScreenshotSaved
```

## 3. 生命周期与后台任务

入口：[MemontaApp.swift](../../Memonta/MemontaApp.swift)、[BackgroundWorker.swift](../../Memonta/Services/BackgroundWorker.swift)、[BackgroundTaskQueue.swift](../../Memonta/Services/BackgroundTaskQueue.swift)。

### 3.1 启动与退出

macOS 关键初始化顺序：`calibrationHook` → `backgroundWorkerHook` → `singleInstanceGuard` → `workerHandshake` → fd 限制提升 → ModelContainer。
带校准或 worker 参数时先处理专用入口；普通重复实例先退出；容器创建前执行 worker 接管。
接管判据是 `DatabaseOwnershipLock`（存储目录下 `.db_ownership.lock` 上的 `flock`）：主应用在宽限内等守护进程让出锁，拿不到就**不打开可写容器**，退化为内存容器并弹窗说明本次运行不落盘；worker 同样先取得锁再开容器，拿不到就保留队列退出。进程退出（含崩溃）由内核释放锁，因此不会出现「PID 已死但锁未释放」。
容器另在持久化失败时回退内存并提示；CloudKit 配置尚未启用。RootView 的隐私同意门控任务串行处理迁移、状态重置、磁盘对账与遗留队列续跑（模型预热是唯一并行的独立任务），具体次序查生命周期 modifier。

退出时若合并进行中，按预计结束时间加余量异步等待（有上下限）；随后**先紧急收尾录音**（分片 finalize 最不可逆），再 `EntryMirrorStore.flush()` 有界等待条目镜像落盘，然后按需拉起 worker、卸载模型，最后**直接结束进程**（`ProcessLimits.exitSkippingStaticDestructors` → `_exit`，跳过 `exit()` 的 C++ 静态析构）：onnxruntime / SherpaOnnx 的静态全局对象在 `__cxa_finalize_ranges` 里析构时会 abort，曾表现为「用过说话人分离后退出应用必崩」。同类 `exit()` 入口（单实例守卫、校准工具、守护进程、隐私拒绝）一律走该助手。
窗口恢复由 AppDelegate / MenuBarController 幂等处理；不能把关窗口等同于退出应用。

### 3.2 产品决策与边界

- 同一应用二进制以 `--background-worker` 启动无 UI 进程，复用服务，不额外建 target。
- 只续跑用户已启动的转写、录音总结、快捷笔记总结任务，并恢复遗留分片；不自动给从未操作的条目发起 AI 请求。
- worker 不阻止系统休眠，唤醒后继续；队列清空自动退出。
- 主应用启动请求 worker 收尾让位，意图是单方持有数据库并消费队列；正常情况下完成当前任务后退出。
- 当前握手默认宽限 15s，超时发 SIGTERM 再等 5s；仍不退出时记录 fault 后继续启动。**极端情况下数据库独占未保证**，详见 [技术债](../TECH_DEBT.md)。
- 视频画面分析不进入后台队列；不能宣称关 App 后可续跑抽帧/视觉请求。

### 3.3 队列与进程协议

| 对象 | 契约 |
|---|---|
| `.background_task_queue.json` | 可配置存储根目录下的持久队列；条目含 kind、folderName、配置 ID/快照及入队时间 |
| STT 快照 | 保存模型、语言和后处理配置；API Key 不落 JSON，执行时从 Keychain 读取 |
| LLM 配置 | 按配置 ID 查找；失配时的 active/首个配置回退见 `execute`，不是快照锁定所有 LLM 参数 |
| 队列写入 | 临时文件替换；读改写使用 flock，消费交接另由握手协调。锁文件打不开时当前实现退化无锁，不宣称绝对互斥 |
| `inProgressID` | 崩溃后清除执行标记，未出队条目视为待续跑；入队按类型和目标幂等去重 |
| PID / stop 文件 | `.background_worker.pid` 与 `.background_worker_stop` 协调存活、停止与接管 |

worker 先恢复分片（不开数据库），再创建自己的 ModelContext 消费队列；不跨进程传 `@Model` 对象。
队列处理由 MainActor Task 与 RunLoop 驱动，不可阻塞主线程使业务回调死锁；当前轮询细节见 `run`。
`drainQueue` 执行后兜底出队，包括找不到目标等路径；旧计划中的 retryCount 重试规则未实现，不能依赖。
快捷笔记在 worker 中生成内容并保存待办，不触发需要界面的提醒事项授权/写入流程。
主应用可复用 `drainQueue` 兜底续跑；异常接管、退出、恢复与双实例回归见 [技术债](../TECH_DEBT.md)。

### 3.4 应用内处理队列（TaskCenter）

[TaskCenter.swift](../../Memonta/Services/TaskCenter.swift) 是进程级单例（`@MainActor @Observable`），把应用内所有「可排队的处理任务」统一到一处调度与展示，与上文的 `BackgroundTaskQueue`（跨进程、守护进程消费）是**两套不同机制**：前者只活在主应用进程内，后者是磁盘持久队列。

- **任务种类**（`TaskKind`）：下载模型 / 转写 / 画面分析 / 总结 / 润色标题 / 拆解待办，并给每种资源类分类。录音与录屏是实时会话，必须立即开始，**不进本队列**。
- **调度**：同时运行的 Job 上限 `maxConcurrentJobs = 3`；Job 由若干 `Step` 按顺序执行。资源类再由 `AsyncClassGate` 限流——本地推理（转写 / 画面分析）1、下载 1、网络 LLM 3，与「单实例推理串行门」叠加不冲突（那个门保护底层推理实例，这个门保护调度层步骤数）。
- **一键处理**：不摊平成多个独立 Job，而是**一个父 Job 内含多个顺序子步骤**（转写 → 画面分析 → 总结 → 拆解待办），以免破坏「转写先备模型、总结后自动润色标题」这类既有依赖。Job 名取当前条目标题。入队前先经 `OneClickPlan`（纯数据，可单测）+ `OneClickPreviewView` 出预览：按**产物**判定已完成步骤并默认跳过（仅「重新转写」显式开启才覆盖已有转写；转写有手动编辑时先备份为 `transcript.backup.md`），云端图片 / 视频帧的数据范围也在预览中说明。
- **失败处理与重试**：步骤失败时由执行体上报**稳定错误码**（`TaskErrorCode`，不落英文 `localizedDescription`），调度器补记失败时刻；失败 Job 保留在队列的「最近失败」区，可「重试此步骤」（只重排失败步骤）、「重新执行整个任务」，并按错误码提供打开设置 / 在 Finder 中显示 / 打开系统设置等修复入口。
- **暂停 / 续传**：只有下载模型（`TaskKind.canPause`）支持真正的暂停与续传——暂停即取消底层下载并保留分片与 `.cache` 元数据，继续时重新调度该步即从断点续传；其余任务没有续传游标，暂停等价于取消。
- **只做调度**：每个 Step 的执行体调用既有 ViewModel 方法并 `await` 其 Task，不重写业务逻辑；取消转发到既有 `cancelXxx` 入口。
- **状态恢复**：队列面板重启后能显示「进行中 / 失败」，靠的是模型上的持久化 `ProcessingStatus` 字段（见 [03-数据模型层](03-数据模型层.md) §1.1），而非 TaskCenter 自身的内存状态；失败码与失败时刻只活在本次运行的队列里（重启后不保留）。
- **边界**：TaskCenter 不影响守护进程——应用退到后台后任务语义仍由 §3.3 的握手协议保证；录屏抽帧等画面分析不进后台队列（守护进程无抽帧能力）。

## 4. 磁盘存储布局（权威数据源）

默认存储根目录为 `~/Documents/Memonta/`，可在设置中修改。新条目归入 `yyyy-MM` 月份目录，读取兼容旧平铺目录；录音/笔记共用路径工具，截图按图片笔记保存。文件夹名 `yyyyMMddHHmmss[-N]`：

```
~/Documents/Memonta/
├── 2026-09/20260909103000/               # 一条录音或快捷笔记（截图属于图片笔记）
│   ├── recording.m4a             #   最终录音（分片合并产物）
│   ├── {base}_video.mp4         #   视频导入时留存的原始视频（可选，不加密）
│   ├── frames/kf_NN_秒s.jpg     #   画面要点抽出的关键帧（重新分析时复用缓存）
│   ├── visual.md                #   画面要点（加密镜像，仅视频条目）
│   ├── meta.json                 #   元数据（title/itemType: recording|quicknote）
│   ├── transcript.json           #   转写片段（含说话人）
│   ├── summary.md                #   总结（加密镜像）
│   ├── todos.json                #   AI 待办（加密）
│   ├── source.txt                #   快捷笔记正文（加密）
│   ├── source.png                #   图片笔记/截图最终图片（不加密）
│   ├── ocr.txt                   #   OCR 文本（加密）
│   └── *_mic_tmp_*.caf / *_sys_tmp_*.wav  # PCM 临时分片，停止后合并清理
├── WhisperModel/                 # 本地 Whisper 模型文件夹（用户下载/指定）
├── DiarizationModel/             # 说话人分离模型（segmentation.onnx + embedding.onnx）
├── Voiceprints/                  # 声纹库（<uuid>.json：姓名+向量+modelId）
├── Dictionary/                   # Markdown 词典（纠正词条 + PII 标记词条）
└── url_diagnostic.txt            # 提醒事项 URL 诊断输出（一次性）
```

**双向同步**：`FileSyncService` 启动时扫描上述目录，把磁盘上的录音/笔记补录进数据库（数据库是磁盘的镜像）；删除操作先删磁盘再删 DB 记录（防"复活"）。

## 5. 并发模型（Swift 6 严格并发）

| 场景 | 方案 |
|------|------|
| UI 绑定服务 | `@MainActor @Observable final class` + `shared` 单例 |
| 后台音频线程回调 | `installTap` / `SCStreamOutput` 闭包运行在实时音频线程，所在服务**不标 @MainActor**，用 `nonisolated` + `@unchecked Sendable` 包装盒封装 `AVAudioFile` 等非 Sendable 对象 |
| 单实例推理引擎 | WhisperKit/sherpa-onnx 不支持并发，经 **actor 串行门（异步信号量）** 排队 |
| 跨 actor 访问 | 模型引用使用同步保护的 `ModelBox`；SwiftData 对象改为 ID 或值类型快照（`LLMConfigSnapshot`），不靠 unsafe 标注绕过同步 |
| C 回调桥接 | CoreAudio/Carbon 回调内 `Task { @MainActor in }` 跳回主线程；AppKit 同步回调用 `MainActor.assumeOnMainThread`（规避 macOS 26 executor 断言） |
| 取消传播 | 长任务 `Task.checkCancellation()`；WhisperKit 回调沿用显式取消标志，调用方取消须转发到推理 |
| 首次创建竞态 | Keychain 密钥等"读不到就创建"模式：锁 + 双重检查 + 内存缓存 |

并发与回调经验见 [项目实践](../../DEVELOPMENT_GUIDE.md) §2。

## 6. 通知总线（ NotificationCenter 解耦）

跨组件通信统一走自定义 `Notification.Name`（定义见 `ScreenshotNotifications.swift` 与各服务）：

| 通知 | 发送方 | 接收方 |
|------|--------|--------|
| `screenshotHotkeyPressed` / `fullscreenScreenshotHotkeyPressed` | GlobalHotkeyManager | RootView → ScreenshotManager |
| `recordingHotkeyPressed` | GlobalHotkeyManager | RootView → `toggleMeetingRecording()`（录音全局热键 ⌃⌘R） |
| `menuBarStartRecording` / `menuBarStopRecording` | MenuBarController | RootView → RecordingViewModel |
| `menuBarStartScreenshot` / `menuBarStartDelayedScreenshot` | MenuBarController | RootView → ScreenshotManager |
| `screenshotCaptureSaved` | ScreenshotManager | RootView → QuickNoteViewModel（转图片笔记） |
| `screenshotPermissionNeeded` / `screenshotErrorOccurred` | ScreenshotManager | RootView（弹窗） |
| `menuBarOpenSettings` / `openHelp` / `menuBarCreateQuickNoteFromClipboard` | MenuBarController / 菜单命令 | RootView |
| `MemontaShowMainWindowFromOtherInstance`（分布式通知） | 新实例退出前 | 旧实例 AppDelegate（恢复主窗口） |

## 7. 架构特征总结

1. **服务单例化**：状态型系统服务多为 `@MainActor @Observable` 单例，纯计算与音频回调有独立隔离边界，ViewModel 直接持有引用，简单直接（牺牲可测试性换取跨模块访问便利）
2. **文件系统权威 + 数据库索引**：任何 SwiftData 记录都能从磁盘文件夹重建，是本项目数据可靠性的基石
3. **渐进降级**：调用方加密失败回退明文并通知（读路径 `decryptSafely` 兼容）、数据库失败回退内存、混音失败回退单轨、分离失败回退无说话人、声纹失败静默跳过——每个环节都有降级路径
4. **平台守卫内联**：macOS 专属代码（AppKit/Carbon/ScreenCaptureKit/AX）以 `#if os(macOS)` 内联在共享文件中，而非分目录
5. **处理任务统一入队**：应用内可排队任务（下载 / 转写 / 画面分析 / 总结 / 润色标题 / 拆解待办）收敛到 `TaskCenter`（最多 3 并发 + 资源类限流），「一键处理」是单个父 Job 的顺序子步骤；与跨进程后台队列分工明确
