# 13 · 构建与运行

## 1. 工程与环境

[project.yml](../../project.yml) 是 XcodeGen 配置源：`deploymentTarget`、`SWIFT_VERSION`、`xcodeVersion`、targets、签名与依赖均以它为准。
当前声明 macOS 15 最低部署、Swift 6 语言模式和 Xcode 27 工程版本；构建工具链还需包含源码引用的新 SDK API。
最低应用运行版本不等于开发机最低版本；不要沿用旧文档“macOS 13 + Xcode 16 即可构建”的假设。

`Memonta`、`MemontaTests`（Swift Testing 单元测试）与 `MemontaUITests`（XCUITest）均为 macOS target（工程已取消 iOS 支持，iOS 分享扩展 target 与相关代码已删除）。

## 2. 构建与测试命令

在项目目录运行；若 Xcode 安装位置不同，替换 `DEVELOPER_DIR`。这也避免 `xcode-select` 指向 Command Line Tools 时找不到完整 SDK。

```sh
# 首次生成，或源文件增删、依赖/工程配置变化后运行；仅改文档不用执行
xcodegen generate

# macOS Debug
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -project Memonta.xcodeproj -scheme Memonta -configuration Debug -destination 'platform=macOS' build

# Swift Testing（单元测试；UI 测试需 GUI 会话与辅助功能授权，见 §5）
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -project Memonta.xcodeproj -scheme Memonta -configuration Debug -destination 'platform=macOS' test -only-testing:MemontaTests

# XCUITest（冒烟 + 无障碍审计 + 多语言/RTL/伪本地化截图基线）
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -project Memonta.xcodeproj -scheme Memonta -configuration Debug -destination 'platform=macOS' test -only-testing:MemontaUITests
```

不要手改生成的 `.xcodeproj`。签名团队不可用时按本机环境配置后重生成工程。
测试 target 的 `TEST_HOST` 在 `project.yml` 中显式指向 app 内部可执行文件（`Contents/MacOS`），勿改回缺少该路径的旧值。
改了 `Scripts/` 下的构建脚本后必须重新执行 `xcodegen generate`：脚本内容在生成阶段写进工程，否则构建仍跑旧副本。

## 3. 模型与首次运行

- 首启隐私同意后展示引导；引导内含「准备模型」页，可直接下载转写模型与说话人分离模型（源/档位与设置页同源，步骤见下）。麦克风、屏幕录制、辅助功能、提醒事项按功能请求。
- 本地 Whisper 通过设置选择模型文件夹，默认目录由 `WhisperModelFolder.defaultPath` 提供；模型与 tokenizer 文件须完整，加载逻辑会解析子目录。
- 设置页「下载模型」可按档位下载（`WhisperModelOption.catalog`），源可选 HuggingFace 官方或 HF-Mirror 镜像（默认镜像，见 `WhisperModelSource`）；下载走 `WhisperKit.download` 并显式传 endpoint，完成后从 `<模型文件夹>/models/<repo>/<档位>` 重命名到 `<模型文件夹>/<档位>`，随即加载该模型。下载任务经全局处理队列（`TaskCenter.whisperDownloadJob`），是**唯一支持真正暂停 / 续传**的任务：取消（含暂停触发的取消）保留已落盘分片与 `.cache` 元数据，继续时重新调度该步即从断点续传。
- 当前工程排除 `Resources/Models/**`，不要假设 App 内置 tiny/base/small/medium；模型只能由用户手动放置或经上述下载获得。
- 说话人分离模型由设置页下载，或指定包含 segmentation.onnx / embedding.onnx 的目录。下载与 Whisper 统一为「取消保留、重下续传」：`SpeakerDiarizationService.downloadFile` 用 URLSession 流式写临时文件，取消时把 `resumeData` 落盘为 `.resume`，重下时以 `downloadTask(withResumeData:)` 从断点继续。
- LLM 设置使用 OpenAI 兼容服务；请求端沿用 URL 校验，回环 HTTP 豁免与任意局域网 HTTP 是不同情况。

## 4. 脚本与资源

| 脚本 | 用途 |
|---|---|
| [fix_onnxruntime_framework.sh](../../Scripts/fix_onnxruntime_framework.sh) | preBuild 修复动态 framework 布局和引用，避免嵌入签名/启动失败 |
| [verify_embedded_frameworks.sh](../../Scripts/verify_embedded_frameworks.sh) | postBuild 重签 Xcode Run/Test 会优先加载的构建目录框架，并校验 `SherpaOnnxC` 引用与签名 |
| [bump_build_number.sh](../../Scripts/bump_build_number.sh) | Release postCompile 自动递增构建号 |
| [bump_version.sh](../../Scripts/bump_version.sh) | 发布时手动 `patch` / `minor` / `major` 更新营销版本，之后重生成工程 |

**ONNX Runtime 产物修复与校验**（启动崩溃防线）：

- 上游 sherpa-onnx/onnxruntime 动态产物有两个打包问题：framework 用实体目录替代符号链接（嵌入后签名严格校验失败），以及 `SherpaOnnxC` 引用 `@rpath/libonnxruntime.dylib`（该 dylib 并不随包，启动即 `Library not loaded`）。
- 修复脚本只定位**本次构建**的产物：`BUILD_DIR` / `BUILD_ROOT` 都是 `…/DerivedData/<工程>/Build/Products`（不含配置目录），`SourcePackages/artifacts` 位于其上级目录（`../../`）；另支持 `OBJROOT` 与仓库内 `.packages`（自定义 packageCachePath）。它不再遍历其他工程的 DerivedData；`install_name_tool` 修复失败会直接让构建失败。
- SwiftPM 会同时生成 `$(CONFIGURATION_BUILD_DIR)` 副本与 App 嵌入副本。Xcode Run/Test 会通过 `DYLD_LIBRARY_PATH` 优先加载前者；`install_name_tool` 又会使上游签名失效，因此 postBuild 需用与 App 一致的身份重签构建目录副本。校验脚本同时检查两处的引用与签名，防止「构建成功、调试或测试启动即被 AMFI 终止」。
- `Memonta` target 明确关闭 `ENABLE_USER_SCRIPT_SANDBOXING`：上述脚本必须修改 SwiftPM 动态 hash 路径下的二进制产物，并让 `codesign` 递归读取 framework 及其扩展属性，无法用固定的 Run Script Input/Output 列表完整声明。该设置只影响构建脚本的执行沙箱，不会关闭 App Hardened Runtime 或最终代码签名。

`Scripts/add_*l10n*.py` 属一次性本地化维护工具，不是正常构建必需步骤。
`Scripts/fill_empty_l10n.py` 用于补齐 `Localizable.xcstrings` 的空条目：静态解析各 `add_*l10n*.py` 的 `add(源文, [20 语言])` 取值（**不执行**它们，部分脚本无 `__main__` 守卫、导入即写文件），只写当前缺少译文的键与缺失的 zh-Hans 源文条目，已有译文一律不覆盖；写入前校验占位符种类/数量与源文一致，并列出仍未覆盖的键。
用户文案位于 `Localizable.xcstrings`；语言列表由 `knownRegions` 和实际资源决定。修改占位符需核对各语言类型。
图标尺寸生成前核查当前源图路径及 Assets 引用，不依赖旧文档中的 `icon.png` 假设。

## 5. 测试覆盖与验证边界

- [MemontaTests.swift](../../MemontaTests/MemontaTests.swift)：时长、状态/配置、导入与视频命名、关键帧指纹与事件/名额纯函数、导出文档等。
- [KeyframeExtractorTests.swift](../../MemontaTests/KeyframeExtractorTests.swift)：代表帧跨时间窗判重与名额回填、`LLMService.visualChunks` 分段送帧（与上一行的分工：本文件只测这两个不变式）。
- [StabilityRegressionTests.swift](../../MemontaTests/StabilityRegressionTests.swift)：看门狗、可取消门闸、流式合批、超时预算、磁盘节拍、临时目录唯一性、失败报告、词典扫描等。
- [WhisperModelDownloadTests.swift](../../MemontaTests/WhisperModelDownloadTests.swift)：模型档位名（glob 唯一性/精确仓库目录名）、下载源端点与默认值、`HF_ENDPOINT` 写入、三件套就绪判定与档位隔离（均为纯逻辑，不联网）。
- 不在文档维护测试数量或“永久通过”结论；以当前源码及实际执行结果为准。
- 类型检查不覆盖链接、签名和运行时；音频设备、权限、Keychain、窗口、恢复及 worker 需按 [回归场景](../TECH_DEBT.md) 选择实测。

## 6. SDK 兼容经验

- AudioConverter 在 macOS 26+ 使用 provider/receiver 异步路径，保留旧系统 Reader/Writer 实现。
- SystemAudioCaptureService 的新实时写入路径使用 SampleBufferReceiver；MicCaptureService 的 macOS 27+ 路径使用只读 tap。
- 新 API 通过 availability 分支接入，不能为消除弃用警告提高应用最低部署版本。
- `deploymentTarget` 是当前工程使用的键；旧错误键 `deploymentTargets` 曾导致最低系统版本未正确生成。

## 7. 调试与常见问题

| 场景 | 入口 |
|---|---|
| 分离阈值校准 | 应用可执行文件 `--calibrate-diarization <音频> [阈值或 centroid/refine 模式] [模型目录]`；参数以 DiarizationCalibrator 为准 |
| worker 调试 | 应用可执行文件 `--background-worker` 会真实消费持久队列，仅对隔离测试数据使用；协议见架构 §3 |
| 提醒事项 URL | `reminders_url_diagnostic` 偏好控制 RemindersURLDiagnostic；诊断文件不作为常驻上下文 |
| 长录音保存失败 | 检查句柄数、磁盘和 PersistenceReporting 日志；启动 fd 限制提升见 ProcessLimits |
| 系统音频无声 | 检查屏幕录制权限、重启提示和首包 PTS 对齐 |
| 热键/语言不生效 | 检查用户热键配置、系统冲突；语言设置写 AppleLanguages 后重启 |
| TCC 调试 | 仅明确的开发排障使用 DEBUG 清理路径，不在发布版自动重置授权 |

发布、许可证与开源准备统一见 [发布检查](../RELEASE_CHECKLIST.md)。
