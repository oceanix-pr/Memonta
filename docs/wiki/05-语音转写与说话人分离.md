# 05 · 语音转写与说话人分离

[← 返回首页](Home.md) · 源码目录：Memonta/Services

本篇覆盖"音频 → 带说话人标注的纠正后转写文本"的完整管线：

```
音频文件
 ├── 本地：WhisperLocalService（WhisperKit / CoreML）
 └── 云端：WhisperAPIService（OpenAI Whisper API，>25MB 分片）
        ↓ TranscriptionResult（带时间戳的 segments）
 ├── SpeakerDiarizationService（可选）说话人分离 → 回填 speaker
 │    ├── VoiceprintStore 声纹识别（可选）→ 替换为注册姓名
 │    └── DiarizationCalibrator（开发期校准工具）
 ├── ChineseConverterService 繁简归一化
 ├── TranscriptDictionaryService 词典纠正（精确 + 拼音）
 └── TranscriptCache（UI 渲染缓存，加速重复打开）
```

## 1. WhisperLocalService — 本地转写

### 1.1 模型管理

| 成员 | 说明 |

### 1.2 转写执行

```swift
func transcribe(audioPath: URL, decodeOptions: DecodingOptions,
                callback: ((TranscriptionProgress) -> Bool?)?) async throws -> TranscriptionResult
```

- `DecodingOptions(task: .transcribe, language: <STTConfig.language>, temperature: 0.0)`
- `callback` 返回 `Bool?` 控制取消：沿用显式取消标志并返回 false；不能仅依赖回调所在 Task 的取消状态
- 输出 `TranscriptionResult`：文本 + 起止时间 + 说话人字段（供后续回填）

### 1.3 WhisperKit 配置约定

| 参数 | 值 |
|------|-----|
| `modelFolder` / `tokenizerFolder` | 同一目录（tokenizer 与模型同放） |
| 模型来源 | 用户指定目录，加载前校验；不依赖 Bundle 内置或自动下载完整模型 |

## 3. SpeakerDiarizationService — 说话人分离

源码：[SpeakerDiarizationService.swift](../../Memonta/Services/SpeakerDiarizationService.swift)

### 3.1 技术方案

sherpa-onnx 离线说话人日志（**纯 CPU 推理**，说话人数量自动估计）：

- **分段**：pyannote segmentation 3.0 的 ONNX 导出；滑窗步长 `windowShiftRatio` 由**精细度档位**决定（`0.10` = 90% 重叠，sherpa 默认；`0.40` = 60% 重叠，最省；默认档 `0.25`）；窗口秒数由模型元数据决定（pyannote segmentation-3.0 为 5s），步长 = ratio × 窗口
- **声纹嵌入**：3D-Speaker eres2net（embedding.onnx）
- **聚类**：fast clustering（快速聚类）
- **线程**：`DiarizationThreads.resolved`（专业模式可调，区间 2…逻辑核心数−1，默认沿用历史「核心数−2、封顶 6」），分段/嵌入两模型共用；本阶段无 QoS/thermal 退让，长录音时风扇拉高属预期，降载手段见精细度档位、CPU 核心数与 `refineClusters` 采样上限
- **模型位置**：`~/Documents/Memonta/DiarizationModel/`（segmentation.onnx + embedding.onnx），设置页一键从 GitHub Releases 下载（免 HuggingFace token），也支持手动放入
- 下载与推理各有**串行门**，防并发踩踏

### 3.2 主流程

| 方法 | 职责 |
|------|------|
| `diarizeWithSamples` | 构建 `sherpaOnnxOfflineSpeakerDiarizationConfig` → 执行 VAD/segmentation → embedding → fast clustering → 调用 `refineClusters` 精修 |
| 说话人回填 | 将 `TranscriptionResult` 片段与分离结果按**时间重叠最大原则**匹配，回填 `speaker`（"说话人 1"）；可选接声纹识别替换姓名 |
| `refineClusters` | 簇后处理精修（见下） |

### 3.3 refineClusters 三阶段精修（关键设计）

快速聚类常把同一人拆成多簇（实测双人录音出 9~13 簇），三阶段修复：

1. **高相似合并**：同人拆簇相似度高（校准值：同人 0.903 vs 跨人 ≤0.68），阈值 **>0.60** 迭代合并
2. **碎片簇聚拢**：时长 < max(3s, 总时长 5%) 的碎片簇之间以 **0.50** 放宽阈值聚拢
3. **碎片并入大簇**：剩余碎片并入最相似的大簇

最终按时长降序重编号（**说话人 1 = 说得最多的人**），并产出各说话人**质心嵌入**——直接供声纹识别复用，不重复提取。

> 二遍提取的 CPU 约束：主 `process` 内部已对每段算过一次嵌入，但 sherpa wrapper 不暴露这些嵌入，精修只能重建提取器再算一遍；因此选段统一由纯函数 `embeddingSegmentsBySpeaker` 控制：过滤 ≥1.5s 后**每说话人只取时长最长的 `maxSegmentsPerSpeaker`（30）段**（长片段信息量更高，质心质量与全量提取等价）。风扇狂转整改前这里是对全部有效段无上限重提。

**质心构造三处必须同源**（选段规则 + 加权方式）：整段精修 `refineClusters`、分段模式的全局质心、注册流程 `extractVoiceprint`。三者都走「过滤 ≥1.5s → 取最长 30 段 → **按时长加权**平均 → L2 归一化」。回归用例见 [DiarizationSegmentationTests.swift](../../MemontaTests/DiarizationSegmentationTests.swift)、[VoiceprintMergeTests.swift](../../MemontaTests/VoiceprintMergeTests.swift)（含注册侧与识别侧选段一致性）。

### 3.3.1 长录音分段处理（超过 `maxDirectDuration`，默认 30 分钟）

纯计算部分在 `DiarizationSegmentationPlanner`（时长/内存估算、阈值判定、切分含重叠、重叠区去重、跨段身份合并、按时长重编号），逐段推理在 `diarizeSegmented`：

- 按 `segmentDuration`（8 分钟）切分、相邻段重叠 `segmentOverlap`（30 秒）；每段单独 `process` + 段内簇精修，段末即释放采样，**峰值内存 ≈ 单段**。
- 跨段身份合并 `globalSpeakerMapping`：按段顺序把局部编号对齐到全局编号（相似度 ≥ `chunkIdentityMergeThreshold` 0.55 视为同一人），空质心单独占号；相邻段重叠区由 `mergeOverlapping` 去重（前段标签优先）。
- **全局质心不平均各段质心**：早期实现把逐段局部质心等权算术平均，存在权重错配（只讲 20 秒的噪声质心与讲 5 分钟的稳定质心同权）与顺序相关两个缺陷，长会议下同人质心被拉偏。现改为在整段录音上对最终全局说话人**重新按最长 30 段 + 时长加权提取**，与整段路径同源；`weightedCentroid` 逐区间读取，峰值内存 = 单个片段采样（不回到整段常驻）。

### 3.3.2 精细度五档（`DiarizationPrecision`）

专业模式「设置 → 转写 → 说话人分离」暴露的五档，单一轴是**边界与分段精度 ↔ CPU / 内存开销**。持久化键 `diarization_precision`，无保存值或越界回落到中间档。

| 档 | `maxDirectDuration` | `maxDirectMemoryBytes` | `segmentDuration` | `segmentOverlap` | `windowShiftRatio` |
|---|---|---|---|---|---|
| 1 最快 | 10 min | 96 MB | 5 min | 15 s | 0.400 |
| 2 较快 | 20 min | 160 MB | 6 min | 20 s | 0.325 |
| **3 标准（默认）** | **30 min** | **256 MB** | **8 min** | **30 s** | **0.250** |
| 4 精细 | 30 min | 256 MB | 15 min | 45 s | 0.175 |
| 5 最精细 | 30 min | 256 MB | 20 min | 60 s | 0.100 |

设计约束（改档位表时必须同时满足）：

- **中间档严格等于历史默认行为**，默认档不得改变既有结果。
- **整段门槛对所有档位都不超过 30 分钟**。峰值内存由**单次 `process()` 的音频长度**主导（ONNX Runtime 中间张量），不是解码后的采样数组；`maxDirectMemoryBytes` 只约束后者。2026-09-24 用同一条 143 分钟 16k 单声道录音（4 线程）实测：

  | 处理方式 | 峰值内存 | 耗时 | 结果 |
  |---|---|---|---|
  | 分段 12 分钟/段 | 1.68 GB | 12 分 30 秒 | 5 个说话人 |
  | 分段 20 分钟/段 | 2.60 GB | 18 分 13 秒 | 4 个说话人 |
  | **整段（143 分钟一次）** | **8.3 GB** | 14 分 20 秒仍未完成（终止） | — |

  所以「提高 `maxDirectDuration` 换精度」是危险做法：档位越高越应靠**更长的分段 + 更密的窗口**换精度，而不是靠整段。档 4/5 与档 3 的整段门槛相同是**有意为之**，不是笔误。
- **两类参数刻意不随档位变化**：① 嵌入选段上限 `maxSegmentsPerSpeaker`（注册与识别共用，随档变化会让旧档注册的声纹与新档比对的质心错位）；② 聚类与跨段合并阈值 `0.60 / 0.50 / 0.55`（由 `DiarizationCalibrator` 联合标定，脱离校准改数值会把「同人拆簇」变成「两人合并」）。
- 档位在**每次推理开始时解析一次**并向下传递，避免同一次分离里「模式判定」与「实际切分」读到两个不同档位；改档位**不追溯**，需重新转写才生效。`DiarizationCalibrator` 也读同一档位，保证校准结果可直接套用。

### 3.4 稳定性约束

模型缺失 / 分离失败 / 精修失败时**逐级回退**（精修失败用原始聚类结果），任何失败都不影响转写本身。失败只进 `Logger`（`FileSyncService.logWarning`）并在 `applySpeakers` 被 catch 后原样返回结果，因此 UI 上只表现为「转写正常但没有说话人」；分离产出 0 片段同样会留一条 warning，避免只能靠猜。

### 3.5 音频加载 `loadMonoSamples`（曾经的静默失效点）

分离与声纹（`extractVoiceprint`）共用这一个加载器：`AVAudioFile` 逐块读取 + `AVAudioConverter` 重采样到模型要求的 16k 单声道 Float32。加载器分**整段**与**区间**（`timeRange`）两个入口：整段路径用前者，注册与分段全局质心的 `weightedCentroid` 用后者（只读所选片段，不把整段录音读进内存）。两个约束必须同时成立：

- **内存**：不得按整段时长一次分配源缓冲（2h48k 立体声源缓冲≈2.7GB，峰值近 4GB，长会议会被系统直接杀掉且无日志），故按 `sourceChunkFrames`（48000 帧）分块。
- **EOF 出口**：macOS 27 beta (26A428) 上 `AVAudioFile.read(into:)` 读到文件末尾会抛 `NSOSStatusErrorDomain` 的 `eofErr(-39)`，**不返回 0 帧**。因此循环以帧预算（`file.length`）驱动，并把 `eofErr` 当作正常收尾（`isEndOfFileRead`）；只认这一个码，其余解码/权限错误继续上抛，不能伪装成「读完了」。

两者是同一提交里一起改的：只修内存不修 EOF 出口时，每一段音频都会在**全部帧已读出之后**失败，并被上面的静默回退吞掉——表现为升级后说话人与声纹整体不再产出，且日志里只有一条 warning。回归用例见 `MemontaTests/DiarizationAudioLoadTests.swift`（覆盖重采样与直拷两条分支 + 空音频/缺失文件仍报错）。

## 4. VoiceprintStore — 声纹库

源码：[VoiceprintStore.swift](../../Memonta/Services/VoiceprintStore.swift)

### 4.1 存储

- 路径：`~/Documents/Memonta/Voiceprints/<uuid>.json`
- 记录：姓名 + 归一化声纹向量 + `modelId`（**绑定嵌入模型**，换模型后旧声纹自动停用）

### 4.1.1 同名声纹合并

同人声音条件差异大（感冒/远距麦克风）时注册相似度不达查重阈值 0.65，会按同名新建出多条记录。声纹库管理页（设置→声纹库）仅在存在可合并组时展示「合并同名」入口：`VoiceprintStore.mergeSameNameGroups` 按 (name, modelId, dim) 分组，`mergedVoiceprint` 纯计算按 sampleCount 加权质心→ L2 归一化，id/createdAt 沿用最早一条（覆写其文件），来源录音 ID 并集去重；**先写合并结果再删余条**，写失败不丢原数据；不跨模型合并。纯函数+临时目录回归见 `MemontaTests/VoiceprintMergeTests.swift`。

### 4.2 阈值常量

| 常量 | 值 | 用途 |
|------|-----|------|
| `matchThreshold` | 0.5 | 识别命中阈值 |
| `matchMargin` | 0.05 | top1-top2 领先幅度（防歧义） |
| `samePersonThreshold` | 0.65 | 注册查重（≥ 视为同人） |

### 4.3 核心方法

- 加载/保存/删除（JSON 文件读写）
- 相似度计算：L2 归一化 + 余弦相似度

### 4.4 两条业务流程

**流程 A · 注册**（转写结果页"声纹"按钮）：

1. 弹窗每个说话人左侧有**试听按钮**：播放该说话人**最早**出现的片段（`AudioPlayerState.playRange` 从片段起点精确起播、播到片段结束自动暂停，边界检测挂在 0.5s 周期观察者上），便于判断这一串标注到底是谁；音频原件缺失时按钮禁用
2. 为说话人填姓名
3. 按该说话人的片段区间提取嵌入（纯函数 `voiceprintRanges` 选段：过滤 ≥1.5s → 取**时长最长的 30 段**）→ **按时长加权**平均归一化 → 入库。选段与加权与识别侧（`embeddingSegmentsBySpeaker` + `centroid(of:)`）同源，避免「注册向量」与「比对质心」落在两个构造上；只读取所选区间，不把整段录音读进内存
4. 同时批量替换本录音的说话人标注
5. 查重：与库内最高相似声纹比对，≥0.65 同人（同名更新、异名报错）

标记成功后转写页必须立即显示新姓名。写路径统一走 `invalidateTranscriptCache`，它**先清 `TranscriptCache`、再递增 `transcriptVersion`**——顺序颠倒会让 `TranscriptView` 的 `.task(id:)` 抢在清缓存之前命中旧条目，页面停在「说话人 N」且后续没有新的版本变化、不会自愈。

**流程 B · 识别**（转写时，分离完成后）：

1. 先按 (name, modelId, dim) 把同名多条目折叠为单条（`VoiceprintStore.collapsingSameName`）：同人跨场次注册相似度达不到 0.65 会并存多条，不折叠会让同一姓名同时占据 top1/top2，把领先幅度压到 `matchMargin` 以下，使该人**永远无法被识别**
2. 用 `refineClusters` 产出的说话人质心与库比对（**不介入聚类本身**）
3. 命中条件：相似度 ≥0.5 **且** top1-top2 领先 ≥0.05，否则保留"说话人 N"
4. **全局唯一性分配**：小规模采用最大权重匹配（每人 top 3 候选），超过 8 个说话人降级为按分数贪心分配，每个注册声纹最多分配给一个说话人——防止两个不同说话人被标成同一姓名

库为空/失败时**静默回退**，不阻塞转写；开关 `enableVoiceprintRecognition` 默认开启。未命中/歧义都会留一条 warning（含 top1/top2 与领先幅度），便于事后核对识别质量。

## 7. TranscriptDictionaryService — 词典纠正

源码：[TranscriptDictionaryService.swift](../../Memonta/Services/TranscriptDictionaryService.swift)

### 7.1 词典存储与格式

- 位置：`~/Documents/Memonta/Dictionary/` 下的 **Markdown 文件**（设置 → 词典 可视化新建/编辑/删除）
- 条目格式：

```markdown
- 术语                    ← 拼音自动纠正（同音/近音误写替换为"术语"）
| 错误词 | 正确词 |        ← 精确替换
错误词 -> 正确词           ← 精确替换（箭头式）
- 词语 #去标识化:类别      ← PII 词条标记（不参与转写纠正，见 06 篇）
```

### 7.2 纠正算法

`correct(_:)` 两阶段，**精确替换优先**：

1. **精确替换**：字符串直接匹配（长词优先）
2. **拼音匹配**：`applyPinyinCorrection` —— `rawPinyin` 用 `CFStringTransform` 逐字转无声调拼音（去声调、去分隔符归一化），在**连续汉字片段内滑窗**比对读音，相同则替换

### 7.3 执行时机

转写后、繁简归一化之后、加密之前；对已完成转写**不追溯**，重新转写后生效。

## 8. TranscriptCache — 转写渲染缓存

源码：[TranscriptCache.swift](../../Memonta/Services/TranscriptCache.swift)

按录音 ID 缓存"**解密 + 拼接 + Markdown 解析**"后的结果（`SegmentData`：Markdown 文本 + 块结构），避免每次打开详情页重复解密全量片段。

| 方法 | 职责 |
|------|------|
| 缓存读写 | key = 录音 ID；命中直接返回结构化数据 |
| `invalidate` | 编辑片段/重新转写后失效；TranscriptView 用 `transcriptVersion` 计数驱动缓存重建 |

缓存已有 LRU：当前代价上限 64MB、条目上限 24，并至少保留一条；阈值以 `TranscriptCache.Store` 实现为准。编辑/重转写必须失效缓存。
