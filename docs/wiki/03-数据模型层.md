# 03 · 数据模型层

[← 返回首页](Home.md) · 源码目录：[Memonta/Models](../../Memonta/Models)

数据层包含三类角色：

1. **SwiftData 持久化实体**（`@Model`）：`AudioRecording`、`TranscriptSegment`、`LLMConfig`、`QuickNote`；截图作为图片型 `QuickNote` 入库
2. **值类型配置结构**（UserDefaults/Keychain 持久化）：`STTConfig`、`RecordingConfig`
3. **文件级数据结构**：`TodoItem` + `TodoDocument`（todos.json）、`ExportDocuments`（导出）

> SwiftData 注意：`@Model` 宏与计算属性冲突，**所有计算属性放在 `extension` 中**（本项目统一约定）。

## 1. AudioRecording — 录音实体

源码：[AudioRecording.swift](../../Memonta/Models/AudioRecording.swift)

### 1.1 状态枚举（TranscriptionStatus / ProcessingStatus）

```swift
enum TranscriptionStatus: String, Codable {
    case pending      // 待转写（初始态）
    case processing   // 转写中
    case completed    // 已完成
    case failed       // 失败
}

// 通用处理状态：总结 / 画面要点 / 待办拆解（语义与 TranscriptionStatus 对齐）
enum ProcessingStatus: String, Codable {
    case pending      // 未开始
    case processing   // 处理中
    case completed    // 已完成
    case failed       // 失败
}
```

`ProcessingStatus` 为这些任务补上**持久化**状态（过去只存在于 ViewModel 的瞬时属性里，进程重启即丢失），队列面板才能重启后恢复展示「进行中 / 失败」。启动时 `RecordingViewModel.resetStaleProcessingStates` 会把崩溃遗留的 `.processing` 复位为 `.pending`——覆盖 `AudioRecording.transcriptionStatus / summaryStatus / visualStatus / todoStatus` 与 `QuickNote.summaryStatus / todoStatus`。

### 1.2 持久化字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID | 主键 |
| `fileName` | String | 显示名（如"会议录音 2026/9/9 10:30"） |
| `fileExtension` | String | 扩展名（m4a 等） |
| `duration` | TimeInterval | 时长秒 |
| `storedFileName` | String | 磁盘文件名（UUID 命名防冲突） |
| `folderName` | String | 所属磁盘文件夹（`yyyyMMddHHmmss[-N]`） |
| `videoFileName` | String? | 视频导入时留存的原始视频文件名（`{base}_video.{ext}`）；纯录音为 nil，由磁盘扫描按文件名约定重建；「清理视频」后置空 |
| `hasVideoSource` | Bool | 是否为视频条目（录屏 / 导入视频）。与 `videoFileName` 解耦：清理原视频后文件名必须置空（不让模型指向不存在的文件），但该标记保留，列表图标与类型文案不退回「录音」。随 `meta.json` 落盘；旧数据由磁盘扫描按视频文件是否还在补位 |
| `createdAt` | Date | 创建时间 |
| `recordingSource` | RecordingSource | 录音来源 |
| `transcriptionStatus` | TranscriptionStatus | 转写状态 |
| `summaryStatus` | ProcessingStatus | 总结处理状态（供队列面板重启后恢复展示） |
| `visualStatus` | ProcessingStatus | 画面要点处理状态 |
| `todoStatus` | ProcessingStatus | 待办拆解处理状态 |
| `summary` | String? | LLM 总结（**加密存储**） |
| `visualSummary` | String? | 「画面要点」：视频关键帧经多模态 LLM 产出的按时间轴画面记录（**加密存储**）；磁盘镜像 `visual.md` |
| `visualSummaryGeneratedAt` | Date? | 画面要点生成时间 |
| `segments` | [TranscriptSegment] | 级联关系（见下） |

### 1.3 关系建模

```swift
@Relationship(deleteRule: .cascade, inverse: \TranscriptSegment.recording)
var segments: [TranscriptSegment]
```

删除录音时级联删除全部转写片段。

### 1.4 关键方法与计算属性（extension）

| 成员 | 职责 |
|------|------|
| `storageDirectory` / `defaultStorageDirectory` | 存储目录解析：UserDefaults 可配置 key；默认 `~/Documents/Memonta/`；含读取/设置/重置 |
| `createUniqueFolder(from:)` 等文件夹工具 | 文件夹唯一命名：月份目录优先、旧平铺目录兼容；以 mkdir 成败为准原子分配（已存在则追加 `-N` 重试），失败返回 nil，调用方报错 |
| `fullTranscript` | 全部片段解密拼接的纯文本 |
| `transcriptMarkdown` | 片段拼接为 Markdown（含时间戳/说话人） |
| `decryptedSummary` | 解密 summary |
| `formattedDuration` | 时长格式化（`01:23:45`） |
| `saveMetaToFolder()` | 把标题、隐藏状态与 `hasVideoSource` 写盘为 `meta.json` |
| `mediaKind` | 条目类型（录音 / 录屏）：列表图标与类型文案的唯一判据；录屏与导入视频不区分，由 `hasVideoSource` 派生，清理原视频后不回退成录音 |
| `folderIndicatesVideoSource(folderURL:files:)` / `folderHasVisualArtifacts(folderURL:)` | 按文件夹判定视频证据（留存原视频或画面产物），供磁盘扫描与历史条目修复复用 |

## 3. LLMConfig — LLM 配置实体

源码：[LLMConfig.swift](../../Memonta/Models/LLMConfig.swift)

### 3.1 持久化字段（SwiftData）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID | 主键（同时作为 Keychain 存 Key 的键） |
| `name` | String | 配置显示名（"GPT-4o"/"LM Studio 本地"） |
| `baseURL` | String | 服务地址（OpenAI / LM Studio / Ollama） |
| `modelName` | String | 模型名 |
| `isLocal` | Bool | 是否本地服务——决定 PII 脱敏是否启用、URL HTTPS 校验豁免等 |
| `supportsVision` | Bool | 是否支持多模态（图片笔记总结走此分支），默认 false |

### 3.2 计算属性与辅助（extension，@Model 要求）

| 成员 | 职责 |
|------|------|
| `chatCompletionsURL` | baseURL 安全拼接 `/v1/chat/completions` 端点 |
| `apiKey` / `setAPIKey(_:)` | API Key 读写——**计算属性，实际存 Keychain**（`LLMKeychainStore`，service `com.Memonta.llm-apikeys`，以配置 UUID 为键；空值删除） |
| `LLMKeychainStore` | Keychain 存取辅助（KeychainAccess，`.afterFirstUnlock`） |
| 预设模板 | `lmStudioTemplate()`（http://localhost:1234）/ `ollamaTemplate()`（http://localhost:11434）/ `openAITemplate()`（gpt-4o，supportsVision）/ `customTemplate()` |

### 3.3 配置导入导出（换机迁移）

| 成员 | 职责 |
|------|------|
| `LLMConfigTransferFile` | 迁移**负载**格式（`version` / `exportedAt` / `configs[].apiKey`），`Codable + Sendable`，日期 ISO8601；`apiKey` 可选，兼容不含该字段的旧文件 |
| `transferPayload(from:)` | 组装负载（**明文，含 API Key**）。命名即警示：调用方必须先经 `EncryptionService` 加密再落盘，绝不可直接写文件 |
| `decodeTransfer(_:existing:)` | 解析 + 校验 + 去重，返回待插入配置、`[新 id: API Key]` 与统计：字段为空判无效；端点安全**沿用请求路径同一套** `LLMService.validateSecureURL(_:isLocalModel:)`（明文 HTTP 只放行本地模型）；与现有配置按 `baseURL`（去尾斜杠）+ `modelName` 小写比对跳过重复；单次上限 200 条 |
| `EncryptionService` | 加解密用**本机密钥**（Keychain，设备唯一），与转写、总结等本地文件同一套；因此导出文件**只能在本机导入**，跨 Mac 会解密失败并给出明确提示（详见 [同步与安全](08-数据同步与安全.md) §3.5） |
| `LLMConfigExportDocument` | `FileDocument`（见 [ExportDocuments.swift](../../Memonta/Models/ExportDocuments.swift)）：只承载已加密字节，失败早于用户选完保存路径暴露 |

入口：设置 → 大模型 → 配置迁移。导出**不需用户设密码**：负载用本机密钥（`EncryptionService`）加密后落盘，API Key 随配置一起迁移；导入时自动解密，非密文（旧版未加密导出）按明文解析兼容。**边界**：密钥是本机 Keychain 唯一的，所以导出文件**只能在本机 Memonta 导入**，跨 Mac 解密失败并给出明确提示。导入的配置以新 UUID 落库，API Key 写入 Keychain 中对应的新 id；原本没有激活配置时自动激活第一条。

运行期 LLMService 不直接跨 actor 传此对象，而是转成 `LLMConfigSnapshot` 值快照（[LLMService.swift](../../Memonta/Services/LLMService.swift)）。

## 4. QuickNote — 快捷笔记实体

源码：[QuickNote.swift](../../Memonta/Models/QuickNote.swift)

| 成员 | 职责 |

## 5. STTConfig — 转写配置（值类型）

源码：[STTConfig.swift](../../Memonta/Models/STTConfig.swift)

enum RecordingSource: String {   // 录音来源

## 7. TodoItem / TodoDocument — 待办

源码：[TodoItem.swift](../../Memonta/Models/TodoItem.swift)

```swift
enum TodoPriority: Int { case none, low, normal, high }
enum TodoStatus: String { case pending, written, failed }   // 写入提醒事项的结果状态
```

`TodoItem` 结构：`id/title/notes?/url?/dueDate?/alarmOffsetMinutes?/priority/reminderIdentifier?/status/targetListID?`——id 是默认 UUID 字符串，稳定用于去重；targetListID 为空时跟随默认列表。

`TodoDocument`：待办集合的文件持久化，序列化为录音文件夹内 **`todos.json`（加密）**；提供保存/解密读取/删除；写入提醒事项后回填 `reminderIdentifier` 与 `status`，用于删除录音时清理提醒事项残留（先于删文件夹加载）。

## 8. ExportDocuments — 导出文档

源码：[ExportDocuments.swift](../../Memonta/Models/ExportDocuments.swift)

三个 `FileDocument` 实现，供 `fileExporter` 导出：

- `PlainTextDocument`（.txt）
- `MarkdownDocument`（.md）
- `MarkdownPDFDocument`（.pdf）：只携带已排版的 PDF 字节。排版在 `MarkdownPDFRenderer`（Services）里完成：纯 CoreText 分页，不依赖 AppKit/UIKit 类型；先排版后弹保存面板是为了不顶主线程，且排版失败能在用户选路径前报错。应用不提供 PDF 导入，`init(configuration:)` 明确报错

## 10. 持久化分层总览

| 数据 | 存储位置 | 加密 |
|------|----------|------|
| 录音/片段/LLM 配置/快捷笔记 | SwiftData（default.store） | 敏感字段 AES-GCM |
| 转写/总结/OCR/待办文件 | 条目文件夹（transcript.json/summary.md/ocr.txt/todos.json） | 使用现有加密写入与兼容读取；具体边界见安全篇 |
| API Key（Whisper/LLM） | Keychain（.afterFirstUnlock） | 系统级 |
| 加密密钥 | Keychain | 系统级 |
| STT/录音/截图/词典等配置 | UserDefaults | 无（非敏感） |
| 声纹库 | ~/Documents/Memonta/Voiceprints/&lt;uuid&gt;.json | 无（向量数据） |
| 词典 | ~/Documents/Memonta/Dictionary/*.md | 无 |
