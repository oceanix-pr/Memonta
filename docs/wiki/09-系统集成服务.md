# 09 · 系统集成服务

[← 返回首页](Home.md) · 源码：Memonta/Services/

本篇覆盖与操作系统深度集成的辅助服务：菜单栏、全局热键、AppKit 桥接工具。

## 1. MenuBarController — 菜单栏控制器

源码：[MenuBarController.swift](../../Memonta/Services/MenuBarController.swift)（`@MainActor` 单例）

### 1.1 职责

macOS 菜单栏常驻控制中心（`NSStatusBar.system.statusItem`），在主窗口隐藏/共享屏幕场景下提供全部功能入口。

### 1.2 菜单结构（`start()`）

| 菜单项 | 动作 |
|--------|------|
| 开始录音 / 停止录音 | `menuBarStartRecording` / `menuBarStopRecording` 通知 → RootView → RecordingViewModel；录屏进行中状态项显示「录屏中」、切换项显示「停止录制」（依据 `MeetingRecorderService.isScreenRecording`，音频 + 视频轨共用同一停止链路） |
| 捕获屏幕（子菜单，原「截图」+「录屏」两项合并） | 截图组：新建区域截图（⌥⌘S）/截取窗口/截取全屏 → `menuBarStartScreenshot`（带 mode），进统一捕获会话（会话工具栏含「录制」出口）；录屏组：录全屏（鼠标所在屏）一步直达，录选区/录窗口 → `menuBarStartScreenRecording`（带 target），路由到带录制出口的捕获会话（intent=record，选定目标后自动 3 秒倒计时）；尾部声源/质量 radio 为独立偏好 `screen_recording_source/quality`（与设置页「捕获」节同键），不影响会议录音设置 |
| 麦克风（子菜单，与「捕获屏幕」同级、紧随其下） | 列系统全部输入设备（`MicrophoneDeviceRegistry`，含虚拟/回环设备，勾选当前项，已选设备拔出时占位提示）；与设置页「录音 → 输入设备」、截图会话工具栏 mic 按钮、录音中状态徽章的麦克风菜单共用同一偏好 `microphone_device_uid`。会议录音与录屏都用它，故不再放在「捕获屏幕」子菜单内 |
| 隐藏主窗口 | `NSApp.setActivationPolicy(.accessory)`（隐藏 Dock 图标+主窗，仅留菜单栏——共享屏幕场景） |
| 从剪贴板新建笔记 | `menuBarCreateQuickNoteFromClipboard` → QuickNoteViewModel.createQuickNoteFromClipboard（该命令实际创建的是快捷笔记，名称已由 `AppCommandCatalog` 统一为「从剪贴板新建笔记」） |
| 切换语言（子菜单） | `applyInterfaceLanguage(code)`：写 AppleLanguages + 弹重启询问 |
| 设置 | `menuBarOpenSettings` 通知 |
| 退出 | 常规退出（走 `applicationShouldTerminate` 收尾链，收尾完成后 `_exit` 结束进程以跳过 onnxruntime 静态析构崩溃） |

命令的**名称与快捷键**不在这里各自硬编码：菜单栏、应用菜单（`MemontaApp.commands`）、帮助页「快捷键」小节与设置搜索统一引用 `AppCommandCatalog`（`AppCommandDescriptor`：id / `titleKey` / `CommandShortcut` / `settingsDestination`）。全局热键类命令的显示值实时读 `GlobalHotkeyManager`，用户改完热键后各处立刻同步。

### 1.3 窗口管理

| 方法 | 职责 |
|------|------|
| `showMainWindow()` | 幂等恢复主窗口：makeKeyAndOrderFront + deminiaturize 最小化窗口；维护 `mainWindows` 列表 |
| `applyInterfaceLanguage(_:)` | 语言切换：空 = 跟随系统（清 AppleLanguages）；写偏好后询问重启 |
| `availableLanguages` | 语言清单见源码与本地化资源，菜单显示各语言自称 |

状态图标：`image?.isTemplate = true` 适配深浅色，形状与颜色均由系统处理；录音状态由菜单项文本表达（录音中／录屏中／静音），录屏时切换项显示「停止录制」。

### 1.4 Dock 图标显隐

`NSApp.setActivationPolicy(.regular / .accessory)` 切换；配合 AppDelegate 的 reopen/becomeActive 兜底（见 [02-整体架构](02-整体架构.md) §3）实现"点 Dock 图标即可恢复"。

## 2. GlobalHotkeyManager — 全局热键

源码：[GlobalHotkeyManager.swift](../../Memonta/Services/GlobalHotkeyManager.swift)（`@MainActor` 单例）

### 2.1 技术方案

**Carbon `RegisterEventHotKey`**（应用未激活时也可触发，这是 Carbon API 在现代 macOS 上仍不可替代的场景）。

### 2.2 默认热键

| 热键 | 功能 | 生效范围 |
|------|------|----------|
| `⌃⌘R` | 会议录音开/停切换 | 两种模式 |
| `⌃⌘S` | 区域截图（按默认模式） | 两种模式 |
| `⌃⌘W` | 全屏直拍 | 仅专业模式注册 |

热键组合可配置（UserDefaults 持久化），`start()`启动时加载配置并注册，记录生效组合。设置入口是独立的「设置 → 热键」页（`HotkeySettingsView`），两种模式均可见；该页在普通模式隐藏「全屏直拍热键」一行（对应组合在普通模式本就不注册）。

**录音热键冲突回退**：`⌃⌘R` 被其他应用占用（`RegisterEventHotKey` 返回非 `noErr`）时自动改用备选组合 `⇧⌃⌘R`。回退只针对「当前组合仍是默认值」的情形（判定见纯函数 `recordingFallbackCombination`）——用户显式改过的组合若注册失败就如实报失败，不会被悄悄替换。回退结果只存在内存（`recordingHotkeyFellBack`，设置页据此说明原因），不写入 UserDefaults：持久化的是**用户意图**，因此占用方消失后下次启动会自动回到 `⌃⌘R`。

配置约束（`updateHotkey` / `updateFullscreenHotkey` / `updateRecordingHotkey` 返回具体失败原因，设置页据此提示）：

- 非功能键必须至少带一个修饰键；**F1–F20 可单独使用**（此类组合修饰键为 0，`loadFromDefaults` 以「任一项非 0」判定是否已配置）
- 拒绝应用内重复组合（三条热键两两不得相同，统一由 `isDuplicateOfOtherHotkey` 判定）
- 拒绝系统保留组合 `⌃⌘F`（Cocoa 标准菜单「进入全屏幕」）

注册与失败可见性：三条热键**逐条注册**，单条失败只影响该条（不整体回滚）；失败的热键记入 `unregisteredHotkeys`（error 级日志 + 设置页「热键」页提示），避免旧实现「一条被占用即全部失效且界面无提示」。

### 2.4 事件分发

注册 `EventHandler` → 回调按热键 ID 分发 `NotificationCenter` 通知：

- `.recordingHotkeyPressed` → RootView `toggleMeetingRecording()`（与工具栏「录音」按钮同一动作）
- `.screenshotHotkeyPressed` → RootView 读取 `screenshotDefaultMode` → `ScreenshotManager.startCapture(mode:)`
- `.fullscreenScreenshotHotkeyPressed` → `ScreenshotManager.captureFullScreenDirect()`

注销/重注册：设置变更后先 unregister 再 register。

## 3. MainActor+AssumeOnMainThread — AppKit 桥接工具

源码：[MainActor+AssumeOnMainThread.swift](../../Memonta/Services/MainActor+AssumeOnMainThread.swift)

```swift
extension MainActor {
    /// AppKit 同步回调中安全进入 MainActor
    static func assumeOnMainThread(_ body: @MainActor () -> Void)
}
```

**解决的问题**：AppKit 同步回调（`applicationDidFinishLaunching` 等，无 Task 上下文）直接用 `MainActor.assumeIsolated` 在 macOS 26 上可能触发 executor 断言崩溃；此工具只做主线程检查后直接进入 MainActor 上下文。全项目 AppDelegate 回调统一使用。

## 4. RemindersURLDiagnostic — 提醒事项 URL 诊断

源码：[RemindersURLDiagnostic.swift](../../Memonta/Services/RemindersURLDiagnostic.swift)

一次性诊断工具（详见 [06-LLM总结与智能功能](06-LLM总结与智能功能.md) §4）：`reminders_url_diagnostic` defaults 标记触发，验证 EKReminder 的 URL 字段写入行为，结果写 `~/Documents/Memonta/url_diagnostic.txt`，完成后自动清除标记。

## 5. 系统权限总表

| 权限 | 用途 | 授权方式 |
|------|------|----------|
| 麦克风（NSMicrophoneUsageDescription） | 会议录音 | TCC 弹窗 |
| 屏幕录制 | 系统音频采集（SCStream）+ 截图（SCScreenshotManager） | 系统设置，**授权后需重启应用** |
| 辅助功能（Accessibility） | AppMuteDetector AX 树轮询 | 系统设置 |
| 提醒事项（NSRemindersUsageDescription） | 待办写入 EKReminder | TCC 弹窗 |
| 网络客户端（entitlements） | 云端 API / 模型下载 | entitlements |
| 用户选择文件读写（entitlements） | 导入音频/导出文档 | entitlements |

macOS entitlements（[Memonta.entitlements](../../Memonta/Resources/Memonta.entitlements)）遵循最小权限：`audio-input` + `network.client` + `files.user-selected.read-write`，**未启用** App Sandbox（直写 ~/Documents 需要），**未启用** `cs.disable-library-validation`（安全考量）。工程已取消 iOS 支持，原 iOS 分享扩展的 App Group entitlement 已随扩展删除。
