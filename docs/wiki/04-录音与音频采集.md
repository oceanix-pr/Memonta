# 04 · 录音与音频采集

[← 返回首页](Home.md) · 源码目录：Memonta/Services

本篇覆盖会议录音的完整采集链路：总控编排 + 双路采集 + 静音检测 + 音频工具。

```
MeetingRecorderService（总控，@MainActor @Observable 单例）
 ├── MicCaptureService         麦克风：AVAudioEngine + AVAudioFile（CAF/PCM 分片）
 ├── SystemAudioCaptureService 系统音频：ScreenCaptureKit + AVAssetWriter（WAV/PCM 分片）
 ├── AppMuteDetector           会议 App 静音按钮检测（AX 轮询）
 ├── MicMuteMonitor            系统麦克风静音监听（CoreAudio）
 └── AudioConverter            时长探测 / 格式转换（AVAssetReader/Writer）
```

## 1. MeetingRecorderService — 录音总控

源码：[MeetingRecorderService.swift](../../Memonta/Services/MeetingRecorderService.swift)（`@MainActor @Observable final class`，`shared` 单例）

### 1.1 职责

编排一次会议录音的完整生命周期：磁盘检查 → 目录创建 → 按 `RecordingConfig.source` 启动采集 → 分片轮转 → 停止合并 → 产出最终 m4a。UI 通过 `@Observable` 直接观察其状态（`isRecording`/`elapsedSeconds`/`isMicMuted`/`muteSource`）。

### 1.2 分片滚动架构

| 状态 | 说明 |
|------|------|
| `segmentDuration = 300s` | 每 5 分钟一个分片，限制单文件损坏的影响面 |
| mic 分片 URL 列表 / sys 分片 URL 列表 | 双路各自独立分片 |
| `pendingMergeFinalURL` | 停止后的合并目标路径 |
| PCM 分片文件 | 条目目录内 `*_mic_tmp_*.caf` / `*_sys_tmp_*.wav`，停止后合并清理 |

### 1.3 关键方法

| 方法 | 职责 |
|------|------|
| `startRecording(config:)` | 磁盘预检（≥500MB）→ 创建 `~/Documents/Memonta/yyyy-MM/yyyyMMddHHmmss[-N]/` → 按 source 启动 microphone/systemAudio/mixed 采集 → macOS 系统音频权限预检；返回最终文件 URL |
| `stopRecording()` | 停止计时器/静音监听/全部采集 → `mergeSegments()` 合并 → 返回最终 m4a URL；错误经 `lastError` 传递给 UI |
| 分片轮转 | 每 300s 触发：mic 同步 `rotateSegment()`、sys 异步 `rotateWriter()`；**轮转失败保留旧分片继续写入**，保障不丢数据 |
| `mergeSegments()` | 过滤可播放分片（校验时长/音轨，跳过损坏与静音空段）→ **混合模式下先逐片做参考回声消除**（见 §7）→ 优先 `AVMutableComposition` 双轨混音 → `AVAssetExportSession` 导出 m4a（macOS 15+ async `export(to:as:)`）→ 失败回退单轨拼接 → 清理/保留分片。收尾拆成「检查分片 → 回声消除 → 混音导出 → 保存」四阶段（`mergePhase`），供界面显示当前进度 |
| `finalizeForTermination()` | App 退出时紧急收尾：finalize 临时文件（不完整分片下次启动经 FileSyncService 校验恢复合并） |

### 1.4 易回归约束

句柄峰值、PCM 容器、磁盘阈值、串行写入与 SDK 分支统一见 [项目实践](../../DEVELOPMENT_GUIDE.md) §1；恢复读错不可误删原件见 §3。

## 2. MicCaptureService — 麦克风采集

源码：[MicCaptureService.swift](../../Memonta/Services/MicCaptureService.swift)

**注意**：本类**不标 @MainActor**——`installTap` 闭包在后台实时音频线程执行，若标 @MainActor 闭包会继承主 actor 隔离导致崩溃；用 `nonisolated` 切断隔离。

| 方法 | 职责 |
|------|------|
| 启动采集 | 确认麦克风权限（已授权直接继续；**未决时先发起系统授权请求并等待结果**，仅拒绝/受限才抛错）→ **绑定所选输入设备**（见下「麦克风设备选择」；必须早于读取输入节点格式，格式随设备变化）→ 获取输入节点格式 → 创建 `AVAudioFile` 写 CAF/PCM 分片 → `installTap` → 启动 engine |
| `mute()` / `unmute()` | 运行时静音：**移除 tap 暂停写入、重装 tap 恢复**（避免重启 engine 的中断） |
| 设备切换处理 | 监听 `.AVAudioEngineConfigurationChange`：**重新对齐目标设备**（所选设备仍存在则绑回，已拔出则明确回退系统默认，避免引擎停在消失的设备上继续采到静音）→ 移除旧 tap → 按新输入格式重装 → 重启引擎；设备拔出（sampleRate=0）时暂停等待自动恢复 |

**权限**（`start(to:)` 为 `async`）：只做只读预检不行——系统只在 App **主动请求**后才把应用登记进「麦克风」面板，只读判定会把「未决」当成「拒绝」直接报错，全新机器上既不会弹授权框、也无从手工授权（分发到新机器表现为面板里没有 Memonta）。因此未决时调 `AVAudioApplication.requestRecordPermission()`（macOS 14+）/ `AVCaptureDevice.requestAccess(for:)` 并等待；已拒绝时重复调用不会再次弹窗，直接按错误上报（文案指向系统设置）。

**写入格式**：Linear PCM、采样率取自输入设备、单声道、16-bit、非浮点、非 big-endian、非 interleaved。

**线程安全**：`AVAudioFile` 等非 Sendable 对象用 `@unchecked Sendable` 包装盒封装（访问期不变即可安全）。

**麦克风设备选择**：`MicrophoneDeviceRegistry`（[MicrophoneDeviceRegistry.swift](../../Memonta/Services/MicrophoneDeviceRegistry.swift)）负责枚举系统输入设备、按 UID 持久化选择、把设备绑定到引擎输入节点。

- **枚举**：CoreAudio（`kAudioHardwarePropertyDevices` + 输入流过滤），口径与系统「声音 → 输入」一致，**包含 Loopback 等虚拟/回环设备**（会议软件能用它们，App 不隐藏）。
- **绑定**：AUHAL `kAudioOutputUnitProperty_CurrentDevice`，**不修改系统默认输入设备**，不影响其他应用；未指定时完全不做绑定，引擎跟随系统默认输入设备。
- **回退**：所选设备已拔出时回退系统默认（采集与静音监听同一规则）。
- **标识**：以 CoreAudio Device UID 为准（与 `AVCaptureDevice.uniqueID` 同值）；显示名会重复且随语言变化，不能作为键。
- **性能**：展示用设备列表带 1 秒 TTL 缓存——单次枚举约 0.6ms（20+ 次 CoreAudio IPC），而设置页每次渲染读 3 次、菜单栏每秒读 1 次，逐次直查会在主线程白白累积；**采集决策路径始终直查**，缓存过期不影响录到哪个设备。
- **入口**：设置页「录音 → 输入设备」、菜单栏「麦克风」（顶级项，紧随「捕获屏幕」）、截图会话工具栏 mic 按钮，以及录音中状态徽章的麦克风菜单（该菜单同时承担「静音 / 解除静音」，[RootView.swift](../../Memonta/Views/RootView.swift)）；四处共用同一偏好 `microphone_device_uid`，会议录音与录屏录音同时生效。

## 3. SystemAudioCaptureService — 系统音频采集

源码：[SystemAudioCaptureService.swift](../../Memonta/Services/SystemAudioCaptureService.swift)

基于 **ScreenCaptureKit**（录系统音频也需要"屏幕录制"权限，需重启生效）。

| 方法 | 职责 |
|------|------|
| 启动采集 | 权限检查 → 创建 `SCStream`：`capturesAudio=true`、2 声道、48kHz、`excludesCurrentProcessAudio=true`（防回授）→ 注册音频 + 占位屏幕输出 |
| `SCStreamOutput` 回调 | 只处理 `.audio` 样本；**首包 PTS 启动 writer 会话**（SCStream 时间戳不从 0 开始，固定 `.zero` 会开头空白/与麦克风轨错位）→ `input.append(sampleBuffer)`（写入前检查 `isReadyForMoreMediaData`） |
| `rotateWriter()` | 分片轮转：关闭当前 AVAssetWriter、开启新分片文件（异步） |

**写入格式**：AVAssetWriter 输出 WAV/PCM，48kHz、2 声道、16-bit、`expectsMediaDataInRealTime = true`。

**状态机与清理（重要）**：采集状态是显式的 `idle / starting / running / stopping / failed`，**清理依据是「资源是否存在」而不是某个布尔标志**：

- `start()` 先安装 `SCStream`/writer，再 `await startCapture()`；`startCapture()` 抛错时立即回滚（停流 + finalize writer + 归还 idle），不把残留 writer 留在状态里。
- SCStream 异常停止回调只把状态标为 `failed`，**保留** writer/stream 引用：writer 仍需在 `stop()` 里 finalize（否则当前分片容器不完整、文件句柄泄漏），唤醒重连也依赖它继续写当前分片。
- `stop()` 幂等：没有资源就是空操作，并且只在仍处于 `stopping` 时归位 `idle`，不会踩掉并发启动的新会话。
- 旧实现只有单个 `isCapturing` 标志且 `stop()` 以它为准，上述两条路径都会判定「无需清理」直接返回，遗留未 finalize 的分片与旧 stream。

## 4. AppMuteDetector — 会议 App 静音检测

源码：[AppMuteDetector.swift](../../Memonta/Services/AppMuteDetector.swift)

通过 **Accessibility（AXUIElement）树**推断 Teams/Zoom 等会议软件的麦克风按钮状态。

| 成员 | 职责 |
|------|------|
| 启动检测 | 检查辅助功能权限 → 创建 **1 秒轮询定时器** → `pollMuteState()` |
| AX 树搜索 | 静音按钮识别：优先 `domID == "microphone-button"`（Teams）→ 回退"描述关键词 + 按钮角色"复合匹配（中文关键词必须复合条件，如"取消"+"静音"同时出现，防误判对话框）→ 递归深度限制 35 |

需要用户在系统设置授予"辅助功能"权限。检测结果汇入 `MeetingRecorderService.muteSource`（区分系统静音 / 会议 App 静音），供 UI 提示。

## 5. MicMuteMonitor — 系统麦克风静音监听

源码：[MicMuteMonitor.swift](../../Memonta/Services/MicMuteMonitor.swift)

基于 **CoreAudio `kAudioDevicePropertyMute` 属性监听**：

| 方法 | 职责 |
|------|------|
| 启动监听 | 注册默认输入设备变化监听 + 绑定**当前采集设备**（`MicrophoneDeviceRegistry.resolvedDeviceID()`：跟随已选麦克风，未选或已拔出回退系统默认，与采集绑定同一规则）的 mute 属性监听（设备切换时重新绑定） |
| mute 回调 | **从触发事件的设备（objectID）读取 mute 值**（不重新查默认设备，避免切换瞬间误读）→ 更新 `isSystemMuted` → `onMuteChange` 回调 |

C 回调桥接：`Unmanaged.passUnretained` 传 self，回调内 `Task { @MainActor in }` 跳回主线程；监听对象由单例持有（生命周期长于注册期）。

## 7. EchoReductionService — 离线参考回声消除

源码：[EchoReductionService.swift](../../Memonta/Services/EchoReductionService.swift)（IO 编排）、[EchoCanceller.swift](../../Memonta/Services/EchoCanceller.swift)（DSP 核心，不依赖 AVFoundation，可单测）

**要解决的问题**：远端的话从本地扬声器外放，又被本地麦克风采回，「麦克风轨」里于是混进了「系统音轨」的内容。混音后同一句话出现两份，转写重复、说话人判定也会被打乱。

**只处理可线性建模的那条路径**：本地扬声器 → 本地麦克风（声学回声路径可用自适应滤波还原）。「自己声音绕网络到远端再回来」受远端编码与网络抖动影响，线性滤波无法建模，交给双轨分离转写去重。

| 环节 | 做法 |
|------|------|
| 触发 | `mergeSegments()` 过滤出可播放分片后、混音前逐片处理；`EchoReductionPreference`（默认开启）关闭即跳过；仅两轨都有分片时生效 |
| 时间预算与取消 | 由 `MeetingRecorderService.runEchoReduction` 的独立看门狗兜底（`FileSyncService.echoReductionTimeout`：基础 5 分钟 + 每小时素材 10 分钟，上限 30 分钟）；逐片前检查 `deadline` 与跨隔离 `CancellationFlag`（`MeetingRecorderService.requestCancelEchoReduction`），片内每块也检查取消。超时/取消/算法失败一律把未处理尾部回退为原始音轨，不丢音频、不阻断合并入库；超时后 best-effort 清理残留 `_mic_clean` 临时片 |
| 进度上报 | `reduceEcho(onProgress:)` 每处理完一片回调 (已完成, 总数)，经 `mergePhase == .echoReduction` 暴露给界面（`mergeProgressCompleted/Total` 与 `mergeStageStartedAt`） |
| 延迟估计 | `EchoCanceller.estimateDelay`：抽取到 ~12kHz 做归一化互相关粗搜，再回原采样率精修。延迟含两路启动时间差、声学延迟与播放缓冲，必须实测；相关性过低返回 nil 并按 0 处理 |
| 自适应滤波 | `FrequencyDomainAdaptiveFilter`：约束式 overlap-save 频域 NLMS（窗口 = 2×blockSize，可建模尾长 blockSize = 4096 抽头 ≈ 85ms@48kHz）。归一化必须排在时域梯度约束**之前**——顺序反了会被 1/regularization 放大而发散 |
| 双讲保护 | 每块按「麦克风能量 / 参考能量」判定：本地语音主导时冻结权重更新，避免把用户本人的声音当回声消掉 |
| 采样率 | 以麦克风分片为准；系统音频（48kHz 立体声）由 `AVAudioConverter` 下混并重采样 |
| 输出 | `{base}_mic_tmp_%04d.caf` → `{base}_mic_clean_%04d.caf`，16-bit 单声道 CAF，与麦克风采集同规格，下游零改动 |
| 失败回退 | 任一环节失败即沿用原始分片；只有完整写出（帧数 ≥ 原片）才认账，半成品分片删除。阶段整体超时/被取消时，已算出的清理片保留、其余尾部回退原始音轨 |
| 命名约束 | 清理分片刻意不带 `_mic_tmp`/`_sys_tmp` 标记，否则崩溃恢复会把它当成另一份待合并素材而重复入库 |

片内不做时钟漂移补偿：5 分钟片内的漂移量（典型 50ppm → 15ms）远小于滤波器尾长。控制项只在专业模式的录音设置页暴露，普通模式沿用默认值。

## 8. 一次完整录音的时序

```
[开始] RecordingViewModel.startMeetingRecording(config, context)
   └→ MeetingRecorderService.startRecording
        ├─ 磁盘预检（≥500MB，不足抛错）
        ├─ 建目录 ~/Documents/Memonta/20260909103000/（含 .part/ 分片目录）
        ├─ source == .microphone → MicCaptureService.start（engine+tap）
        ├─ source == .systemAudio → SystemAudioCaptureService.start（SCStream）
        ├─ source == .mixed → 两路并行
        ├─ 启动 elapsed 计时器 + 磁盘复检定时器（<1GB 警告、<200MB 请求停止保存）
        ├─ 启动 AppMuteDetector（AX 轮询）+ MicMuteMonitor（CoreAudio）
        └─ [录音中] 每 300s rotateSegment/rotateWriter 分片轮转
              （麦克风静音时 mute() 移除 tap，恢复时 unmute()）

[停止] stopMeetingRecording(context, source)
   └→ stopRecording
        ├─ 停计时器/静音监听/两路采集（各 flush 最后分片）
        ├─ mergeSegments（四阶段：检查分片 → 回声消除 → 混音导出 → 保存）：
        │    校验分片（时长/音轨）→ [混合模式] 逐片参考回声消除（独立看门狗，可取消）
        │      → AVMutableComposition 双轨 → m4a
        │    失败回退：单轨拼接（保住至少一路）；回声消除超时/取消回退原始音轨
        ├─ 返回最终 URL → AudioConverter.getDuration
        └→ 创建 AudioRecording + context.insert
             + saveContextWithRetry（应对合并后瞬时 fd 耗尽，短退避重试）
             + saveMetaToFolder（meta.json 落盘）

[异常] 录音中崩溃/强杀 → 分片留在 .part/（未 finalize）
   └→ 下次启动 FileSyncService 校验恢复（见 08-数据同步与安全）

[退出] applicationShouldTerminate → finalizeForTermination()
```

## 9. 录屏（屏幕录制 → 视频条目）

实现：**录屏 = 现有录音管线 + 独立视频轨服务**，不新建音频链路。

```
入口（统一「捕获」后）：侧栏「捕获」按钮（仅专业模式；无下拉，目标与出口在会话工具栏）/ 菜单栏「捕获屏幕」子菜单（含录屏直达）/ 会话工具栏「录制」出口
  （RootView.beginScreenRecording → startScreenRecording）
  目标：录全屏（鼠标所在屏）= 一步直达；录选区/录窗口 = 进入带录制出口的
        统一捕获会话（与截图同一冻结屏框选/悬停拾窗），选定目标后自动
        3 秒录制倒计时（RecordCountdownController，点击即开录/Esc 返回会话）；
        拾窗后选区未调整时升级为独立窗口录制（desktopIndependentWindow）
  偏好：声源/质量档位独立存 UserDefaults（screen_recording_source/quality），
        设置页「捕获」节与菜单栏子菜单 radio 共用同一组键
   ↓
RecordingViewModel.startScreenRecording(target, source, quality)
   ├→ MeetingRecorderService.startRecording（双轨 PCM 分片/混音/磁盘止损，原样复用）
   │    文件夹/基名由录音管线分配（yyyyMMddHHmmss）
   └→ ScreenVideoRecorder.start → 同文件夹 {base}_video.mp4（AudioConverter.retainedVideoName 命名约定）
        SCStream → AVAssetWriter **分片化 MP4**（movieFragmentInterval 5s）：
        进程被杀/崩溃时已落盘片段仍可播放，下次启动文件扫描恢复为带视频附件的条目；
        首帧 PTS 定标会话起点，音视频样本保留原始 PTS 由 writer 自动对齐；
        磁盘预检（≥半小时预估）+ 20s 巡检临界回调走统一停止流程；
        拔屏/撤权/关窗 → didStopWithError 只停视频，音频继续并提示
   ↓ 停止（任一入口）：stopMeetingRecording 先 finalize 视频轨→再走原音频合并→
     创建 AudioRecording(videoFileName:) → 条目天然获得「画面」Tab，
     转写/总结（会议·概要双按钮）/关键帧时间轴全链路复用，零模型迁移

约束与限制：
- 停止顺序：音频先合并 → 视频 finalize → **passthrough 混流**（`AudioConverter.embedAudio`：
  mp4 视频轨 + 录音管线混好的完整 m4a（含麦克风）重封装替换原音轨，不转码不损质；
  失败保留原 mp4（可能仅系统声/无声）并提示，不影响条目与音频入库）；
  两源各自从 0 起流，mux 后音频领先画面约启动差（数十至数百 ms，录屏无口型场景接受）
- 视频收尾（`markAsFinished` + `finishWriting`）走 `RacingWatchdog`（上限 120s）：不回调时放弃等待并记为「收尾超时」；超时**不取消 writer**（容器已落盘，取消会毁掉可播片段）。可播性由 `ScreenVideoRecorder.hasPlayableVideoTrack`（容器可解析 + 含时长 > 0 的视频轨）判定，不用文件字节数启发式（静止画面可合法压得很小）
- 只追加「有新画面」的帧（`complete`/`started`；`idle`/`blank`/`suspended` 未生成新帧、无图像数据，追加会让 writer 进入 `failed` 并产出缺 `moov` 的损坏容器）：代价是**静止画面时视频轨短于音频轨**，音频与转写不受影响
- 视频质量档位：高清=原生分辨率30fps≈18GB/h；标准（默认）=长边≤2560px 30fps≈6.8GB/h；省空间=≤1920px 15fps≈2.7GB/h（HEVC，区域/窗口按屏 scale 换算像素后限幅取偶）
- 录屏不进 BackgroundTaskQueue（守护进程无采屏能力，与画面要点同一理由）；退出/崩溃靠分片化 MP4 + 启动扫描兑底
- 录屏中复用会议录音的全部 UI 守卫（徒章/红条/防误退）；声源选择用本次实际值 activeRecordingSource
- 选区 sourceRect 按显示屏内 points（左上原点）传入，输出像素由档位限幅；若实测出现裁剪偏移，优先检查此处坐标系假设
```
