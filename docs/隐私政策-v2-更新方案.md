## 2. 实现结构

### 2.1 唯一事实来源

`Memonta/Services/MemontaPrivacyPolicy.swift`

- `version = "2.0"` / `effectiveDate = "2026-10-19"`
- `sections`：14 节正文（唯一事实来源，首次同意页与设置详情页共用）
- `Section.requiresSeparateConsent`：声纹章节为 `true`，渲染层据此给独立勾选
- `needsConsent(accepted:storedVersion:)` / `needsConsent(defaults:)`
- `accept(voiceprintConsent:at:defaults:)`
- `revoke(defaults:)`
- `voiceprintConsentGranted(defaults:)` / `setVoiceprintConsent(_:defaults:)`

版本规则：

- 未同意 → 需要同意
- 同意过但没有版本号（旧安装）→ 需要同意
- 主版本号变化（`1.x` → `2.x`）→ 需要同意
- 仅次版本号变化（`2.0` → `2.1`）→ 不重复打扰，只在应用内标注最新版本

旧实现只有一个布尔量，因此旧用户升级到 v2.0 时会重新看到同意页。现在所有读取点都走
`needsConsent(...)`，不再需要“启动时把旧布尔量置回 false”的兼容垫片。

### 2.2 渲染与门控

| 文件 | 改动 |

### 2.3 为什么正文放在 Swift 常量而不是 md 资源

`project.yml` 把 `Resources/**/*.md` 排除在 target 之外，Markdown 不会进 App Bundle；
正文放 Swift 常量可以直接被首次同意页与设置页共用，避免两处文案漂移。代价是正文不能像
网页一样独立发布，因此上架前仍需一份内容一致的公开网页（见第 7 节）。

## 3. 已核对的事实（2026-10-19，基于当前源码）

| 正文表述 | 代码依据 |
|---|---|
| 当前未启用 iCloud / CloudKit 同步 | `CloudSyncService` 仅在 `SettingsView` 声明，未被调用；entitlements 无 iCloud 容器；SwiftData 容器未配置 CloudKit |
| 当前未启用自动更新 | 未发现 Sparkle / `SUFeedURL` / 更新检查实现；只有 `docs/GITHUB_AUTO_UPDATE_AND_APP_STORE_PLAN.md` 的方案 |
| 声纹保存在 `~/Documents/Memonta/Voiceprints/`，JSON 明文 | `VoiceprintFolder.defaultPath` + `VoiceprintStore.save`（JSONEncoder，无加密） |
| 声纹不上传 | 注册与比对均只读本机文件；云端请求不含嵌入向量 |
| 辅助功能当前未启用 | `MeetingRecorderService` 中 `setupAppMuteDetector()` 调用被注释；设置开关已标记“当前版本未启用”。正文按“未启动检测”披露，而不是写成正在读取 |
| 提醒事项只在用户点击时写入 | `NSRemindersUsageDescription` + `RemindersService.requestAccess()` 由「写入提醒事项」动作触发 |
| 数据文件夹默认 `~/Documents/Memonta/`，可自定义 | `AudioRecording.defaultStorageDirectory`；设置页「数据管理 → 数据文件夹」支持切换（需重启、不迁移旧数据） |
| 声纹目录不随自定义数据文件夹移动 | `VoiceprintFolder.defaultPath` 固定使用用户文稿目录，不读取数据文件夹偏好 |
| 声纹只能逐条删除 | `VoiceprintLibraryView` 只提供单条删除，没有“一键清空”；正文已按此写明 |
| 联系邮箱 | `SECURITY.md` 的 `feedback@Memonta.app` |

正文明示了三个容易误导的边界：

1. 数据文件夹位于 `~/Documents`，若系统开启「桌面与文稿」iCloud 云盘同步，可能被 **macOS** 同步；这不等于本应用启用了 CloudKit。
2. 云端服务可能位于境外，使用即可能构成跨境传输；建议优先本地模式。
3. `AppMuteDetector` 的实现仍在仓库里，但启动调用被注释；当前版本不会触发辅助功能权限，正文因此写“当前版本未启用”，不写成正在读取 AX。

## 4. `PrivacyInfo.xcprivacy` 的取舍

- **新增** `NSPrivacyCollectedDataTypePhotosorVideos`：云端视觉模型会把截图/关键帧发送到用户配置的服务。
- **不新增** `NSPrivacyCollectedDataTypeSensitiveInfo`：声纹只在本机生成、保存与比对，从不上传；按 Apple 对 “collected” 的口径（数据离开设备并可被访问）不属于收集。若未来增加声纹同步/上传，必须同时补该声明并提升政策主版本号。
- `NSPrivacyTracking` 仍为 `false`，`NSPrivacyTrackingDomains` 为空。
- App Store 的隐私标签必须与政策、PrivacyInfo 三者一致；发布前逐项复核。

## 5. 本地化现状

- v2 新增的 24 个**界面词条**（声纹单独同意、撤回流程、同意状态、辅助功能说明、版本行等）已通过
  `Scripts/add_privacy_v2_l10n.py` 写入 `Localizable.xcstrings`，覆盖 zh-Hans 源文 + 20 种目标语言。
- **协议正文与章节标题仍是简体中文权威版本**，页面内明示「本政策以简体中文版本为准。」。
  因此正文按 `Text(verbatim:)` 渲染，避免“标题被翻译、正文仍是中文”的语言混排。
- 旧的 v1 正文译文仍留在 catalog 中但已不再被引用；不要把它们当作 v2 的译文。
- 若要让非中文用户阅读完整协议，需要人工翻译 14 节正文后把渲染改回 `LocalizedStringKey`，
  并同步更新本说明与 App Store 页面。法律文本不建议未经校对直接机翻上线。
- 重新生成词条：`python3 -B Scripts/add_privacy_v2_l10n.py`。脚本会校验 20 个目标语言齐全、
  占位符一致，只覆盖脚本列出的 24 个 key。

## 6. 验证

本次实际执行：

```sh
xcodegen generate
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project Memonta.xcodeproj -scheme Memonta -configuration Debug \
  -destination 'platform=macOS' build
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project Memonta.xcodeproj -scheme Memonta -configuration Debug \
  -destination 'platform=macOS' test
```

结果：`BUILD SUCCEEDED`；`Test run with 415 tests in 32 suites passed`，其中新增
`PrivacyPolicyTests` 13 个用例（版本语义、旧用户重同意、声纹单独同意持久化、撤回清理、
正文关键披露与绝对化表述回归）。

中间一次全量运行在无关的 `MicCaptureRestartTests` 测试宿主异常重启后报告了两个失败
（`MicCaptureRestartTests.bindingFailureRollsBackAndNextStartCreatesNewEngines`、
`StorageSessionTests.testPreflightRejectsReadOnlyDirectory`）；随后全量重跑 415/415 通过，
单独重跑 `StorageSessionTests` 也通过，判定为测试宿主/音频环境的偶发问题，与本次改动无关。
不把这次失败当作“已验证通过”，发布前仍以干净环境的重跑结果为准。

多语言词条与 `versionLine` 本地化完成后，只重新执行了 `build`（`BUILD SUCCEEDED`），
没有再次重复全量测试；这 13 个隐私测试在词条改动前已通过。若后续再改正文或版本语义，
应至少重跑 `PrivacyPolicyTests`。

未覆盖：本次没有手工启动发布包逐屏走查同意页与撤回退出；发布前需实际验证一次
「旧版本用户升级 → 重新弹同意页 → 勾选/不勾选声纹 → 同意后功能可用 → 撤回后退出」。
